# Release v0.1.0 - Phase 1: Auth Service

**Release Date:** July 16, 2026  
**Phase:** Phase 1 - ASP.NET Auth Service  
**Status:** ✅ Production Ready

---

## 🎯 Overview

First major release of DevSpace implementing a complete authentication service using Clean Architecture, ASP.NET Core 8.0, and PostgreSQL (Neon). This release establishes the security foundation for the entire platform.

---

## ✨ Features

### Authentication Endpoints
- ✅ User registration with email verification
- ✅ Login with JWT + Refresh Token
- ✅ Token refresh with automatic rotation
- ✅ Logout (single device)
- ✅ Logout all devices (revoke-all)
- ✅ Password change
- ✅ Forgot password flow
- ✅ Email verification flow

### Security Features
- ✅ JWT RS256 signing with `kid` header
- ✅ JWKS endpoint (`/.well-known/jwks.json`)
- ✅ Refresh Token Family Rotation with reuse detection
- ✅ SHA-256 token hashing before database storage
- ✅ Soft delete for users
- ✅ Rate limiting (5 login/min, 3 register/min)
- ✅ RFC-7807 Problem Details error format
- ✅ PBKDF2 password hashing (ASP.NET Identity default)

### Architecture
- ✅ Clean Architecture (Domain, Application, Infrastructure, Api)
- ✅ Options Pattern for configuration
- ✅ Policy-based Authorization (`RequireAdmin`, `RequireVerifiedEmail`)
- ✅ Global Query Filters for soft delete
- ✅ No Repository Pattern (EF Core as repository)

### Testing & Quality
- ✅ 16 unit + integration tests (100% pass rate)
- ✅ FluentValidation for request validation
- ✅ GitHub Actions CI pipeline
- ✅ In-memory SQLite for integration tests

### Documentation
- ✅ Scalar API documentation at `/scalar/v1`
- ✅ OpenAPI specification export
- ✅ Phase 1 Retrospective
- ✅ Phase 1 Walkthrough

### Infrastructure
- ✅ Multi-stage Docker build
- ✅ HEALTHCHECK endpoint
- ✅ Neon PostgreSQL integration

## 🔧 Configuration

### Required Environment Variables
```env
DATABASE_URL=Host=xxx.neon.tech;Database=devspace;Username=xxx;Password=xxx;SSL Mode=Require
JWT_PRIVATE_KEY=<base64-encoded-rsa-private-key>
JWT_PUBLIC_KEY=<base64-encoded-rsa-public-key>
CORS_ORIGINS=http://localhost:3000,http://localhost
```

### JWT Configuration
- Algorithm: RS256
- Access Token Lifetime: 15 minutes
- Refresh Token Lifetime: 7 days
- Claims: `sub`, `email`, `role`, `jti`, `name`

## 🚀 Deployment

### Build & Run
```bash
# Restore dependencies
dotnet restore apps/auth-service/Auth.sln

# Build
dotnet build apps/auth-service/Auth.sln --configuration Release

# Run migrations
cd apps/auth-service/src/Auth.Infrastructure
dotnet ef database update --startup-project ../Auth.Api

# Run
dotnet run --project apps/auth-service/src/Auth.Api
```

### Docker
```bash
cd apps/auth-service
docker build -t devspace-auth:v0.1.0 .
docker run -p 5001:8080 \
  -e DATABASE_URL="..." \
  -e JWT_PRIVATE_KEY="..." \
  devspace-auth:v0.1.0
```

## 📝 API Endpoints

### Public Endpoints
- `POST /api/auth/register` - Register new user
- `POST /api/auth/login` - Login
- `POST /api/auth/refresh` - Refresh access token
- `POST /api/auth/forgot-password` - Request password reset
- `POST /api/auth/reset-password` - Reset password
- `GET /api/auth/confirm-email` - Verify email
- `GET /.well-known/jwks.json` - Public keys for JWT verification

### Protected Endpoints (Require JWT)
- `POST /api/auth/logout` - Logout current device
- `POST /api/auth/revoke-all` - Logout all devices
- `GET /api/auth/me` - Get current user profile
- `PUT /api/auth/change-password` - Change password

### Health & Docs
- `GET /health/live` - Liveness probe
- `GET /health/ready` - Readiness probe
- `GET /scalar/v1` - API documentation

## 🔐 Security Notes

- ✅ All passwords hashed with PBKDF2 (100,000 iterations)
- ✅ Tokens stored as SHA-256 hashes in database
- ✅ Rate limiting prevents brute force
- ✅ Soft delete prevents data loss
- ✅ Token reuse detection prevents session hijacking
- ⚠️ HTTPS must be enabled in production (handled by Nginx/Cloudflare)
- ⚠️ JWT keys must be securely stored (use secrets management in production)
